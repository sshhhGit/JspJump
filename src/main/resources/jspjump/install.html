크롬에서 로컬 서버 화면의 버튼·입력칸·그리드 컬럼을 클릭하면 IntelliJ가 그 JSP 줄을 엽니다. 브라우저 쪽은 북마크 하나만 추가하면 됩니다(브라우저당 처음 한 번).

Click a button, input or grid column on a page served by your local server and IntelliJ opens the JSP line that defines it. The browser only needs one bookmark (once per browser).

북마크에는 "IDE에서 스크립트를 받아 오라"는 짧은 코드만 들어 있습니다. 플러그인을 업데이트해도 북마크는 다시 만들 필요가 없고, IDE 포트가 바뀌어도(63342~63361) 자동으로 찾아갑니다. 플러그인만으로는 크롬 화면의 클릭을 가로챌 수 없어서 이 북마크가 필요합니다.

The bookmark only contains a short loader that fetches the script from the IDE, so plugin updates never require a new bookmark, and the IDE is found automatically even when its port changes (63342–63361). It is needed because only a script running in the page can intercept your click; the IDE plugin alone cannot touch the browser page.

3. 사용법3. Usage

  1. 로컬 서버 화면(예: http://localhost:8080/...)에서 북마크 JSP Jump를 누릅니다 → 위쪽에 "요소를 클릭하세요" 안내, 마우스 아래 요소가 파란 상자로 표시됩니다.
  2. 버튼·입력칸·라벨·그리드 헤더나 셀을 한 번 클릭 → IntelliJ에서 JSP 해당 줄이 열립니다. 이 클릭은 화면에 전달되지 않아 실제 저장·조회는 일어나지 않습니다.
  3. 후보가 여러 개면 IntelliJ에 목록이 뜹니다. 결과는 화면 오른쪽 아래에 잠깐 표시됩니다.
  4. 취소: Esc 또는 북마크를 한 번 더 누르기
  1. On your local page (e.g. http://localhost:8080/...) click the JSP Jump bookmark → a banner asks you to click an element and the element under the mouse is outlined in blue.
  2. Click once on a button, input, label or grid header/cell → IntelliJ opens the JSP line. The click is not passed to the page, so nothing is saved or submitted.
  3. With several candidates IntelliJ shows a chooser. The result is shown briefly at the bottom right of the page.
  4. Cancel: Esc or click the bookmark again.

4. 문제 해결4. Troubleshooting

증상해결
"IntelliJ를 찾을 수 없습니다"IntelliJ가 켜져 있고 Settings | Plugins에 JSP Jump가 설치·활성화돼 있는지 확인하세요. IDE 포트를 직접 바꿨다면(Settings | Build, Execution, Deployment | Debugger | Built-in server port) 63342~63361 사이로 두세요. 현재 이 IDE의 포트: {{PORT}}
"Origin not allowed"회사 IP·호스트명(예: http://192.168.0.10:8080)으로 접속한 경우입니다. IntelliJ 오른쪽 아래 알림의 Allow를 누르거나 Settings | Tools | JSP Jump의 허용 Origin에 추가하세요.
"찾지 못했습니다"토스트에 보낸 단서(id·name·문구)가 나옵니다. JSP 안에 그 값이 그대로 없으면(스크립트로 만든 요소 등) 찾을 수 없습니다. 가까운 다른 요소나 감싸는 영역을 클릭해 보세요. 프로젝트가 IntelliJ에 열려 있어야 합니다.
IntelliJ 창이 앞으로 오지 않고 작업표시줄에서 깜빡이기만 함Windows가 다른 프로그램의 창 전환을 막는 경우입니다. 파일은 이미 열려 있으니 작업표시줄의 IntelliJ를 누르세요. 원하지 않으면 Settings | Tools | JSP Jump에서 "Bring the IDE window to front"를 끄세요.
북마크를 눌러도 아무 반응이 없음페이지가 https이거나 보안 정책(CSP)으로 외부 스크립트를 막는 사이트일 수 있습니다. 로컬 개발 서버(http://localhost)에서 사용하세요.
JetBrains IDE를 여러 개 켜 둠북마클릿이 각 IDE에 물어보고 이 화면의 JSP를 가진 IDE에서 엽니다. 마지막으로 성공한 IDE는 기억해 두었다가 먼저 시도합니다.
SymptomFix
"IntelliJ를 찾을 수 없습니다" (IDE not found)Make sure IntelliJ is running and JSP Jump is installed and enabled in Settings | Plugins. If you changed the IDE port (Settings | Build, Execution, Deployment | Debugger | Built-in server port), keep it within 63342–63361. Port of this IDE: {{PORT}}
"Origin not allowed"The page is served from a LAN IP or host name (e.g. http://192.168.0.10:8080). Click Allow in the IntelliJ notification or add it to the allowed origins in Settings | Tools | JSP Jump.
"찾지 못했습니다" (not found)The toast lists the clues that were sent (id, name, text). Elements created by scripts have no literal match in the JSP. Try a nearby element or its container. The project must be open in IntelliJ.
The IntelliJ window only flashes in the taskbarWindows focus-stealing protection. The file is already open; click IntelliJ in the taskbar. You can turn off "Bring the IDE window to front" in Settings | Tools | JSP Jump.
Nothing happens when clicking the bookmarkThe page may be https or block external scripts with a Content Security Policy. Use it on your local dev server (http://localhost).
Several JetBrains IDEs are runningThe bookmarklet asks each IDE and opens the JSP in the one that has it. The last successful IDE is remembered and tried first.
